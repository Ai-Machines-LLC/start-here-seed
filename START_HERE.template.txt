H35 VERSIONS: every file and program carries MAJOR.MINOR.PATCH. The author numbers each build before review (X.Y.1, X.Y.2 ...); each FAIL bumps PATCH; a number is never reused. X.Y.0 = passed review, placed and in use (the placer relabels the passed build X.Y.0 and cites both hashes). MINOR = a new feature or fix set. MAJOR (X) is project wide: every program and file in one project (PLC programs, HMIs, other programs and their docs) carries the same X at all times. A cross-platform update (shared libraries, definitions, objects) moves every one of them to the next X together, changed or not, so a matching X means compatible. How-tos and libraries point to this rule; they don't restate it. Reviews, placements and messages cite version + hash; a date-time is only a timestamp beside it. CHECK: every review, placement and message line has version + sha; every review and placement confirms the new build's X equals the project's current X, or, for a cross-platform update, the X of every other build in that same update set, and the set is placed together; any other mismatch is a FAIL; a version label that is not plain MAJOR.MINOR.PATCH digits (such as 'b', 'rev c' or '1.2.3b') is a FAIL (a repeated correction from the Designer), and the reviewer and the placer reject it; the reviewer scripts this check: every version label in the build and its messages matches ^\d+\.\d+\.\d+$.
