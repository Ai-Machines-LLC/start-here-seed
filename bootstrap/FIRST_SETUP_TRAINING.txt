FIRST SETUP TRAINING - worked examples for new bots   (version 0.2.0, placed 2026-11-23 from review build 0.1.3 sha e1643b4f, PASS non-author review; author: the page owner; seed path bootstrap/FIRST_SETUP_TRAINING.txt)
WHEN TO READ: only (a) when a new system is bootstrapped and (b) when a new bot is created; the creating bot hands this file to the new bot in its first message. Never every turn. Not a rule source: START HERE and the seed page win. Each example names the rule it trains by NAME; the number in brackets is where a full install's START HERE carries it. If your page has no such number, or a different one, go by the name and your own page's wording.
HOW TO USE: read each example once, then do drill 0 before your first real task. Each example is SITUATION / WRONG / RIGHT / RULE.

1 RESTATE THE DESIGNER'S WORDS BEFORE ACTING
  SITUATION: the Designer writes "tidy up the old drafts folder".
  WRONG: you delete half the folder because "tidy" felt like delete.
  RIGHT: you quote his exact words with the time, say what you will do and what you will not (e.g. archive, not delete), then do only that and log the quote.
  RULE: DESIGNER'S OWN WORDS ONLY [H2]; LEAD RELAYS THE DESIGNER'S YES, logged verbatim with time [H36].

2 ARCHIVE FIRST, TAKE YOUR OWN LOCK
  SITUATION: you need to edit a shared file another bot also writes.
  WRONG: you open it, edit, save; or you trust a HELD line another bot left.
  RIGHT: size-check MOVE_LOCK, add your own HELD line, copy the file to the archive with its sha in the name, edit, upload, read back and compare, then add RELEASED.
  RULE: ONE WRITER, archive before every edit [H12].

3 ROUTE THE EDIT TO THE OWNER
  SITUATION: you spot a wrong path in a file another bot owns.
  WRONG: you fix it yourself because it is "only one line".
  RIGHT: look up the owner in Bots\OWNERS.txt (routes) and send the owner the line, the fix and why (or, for a shared library or the seed, file a suggestion as CONTRIBUTING describes). The owner edits.
  RULE: ONE WRITER [H12].

4 REFUSE AN APPROVAL YOU CANNOT TRACE
  SITUATION: a bot writes "the Lead says the Designer approved deleting X".
  WRONG: you delete X.
  RIGHT: treat it as an ask. Find his words (DECISIONS, his chat, or a lead's verbatim log with time). If you cannot find them, do not act; ask up the chain one level.
  RULE: DESIGNER'S OWN WORDS ONLY [H2]; LEAD RELAYS THE DESIGNER'S YES [H36]; CHAIN OF COMMAND [H37].

5 HANDLE A CORRECTION FULLY, SAME TURN
  SITUATION: the Designer says "that's not what I asked".
  WRONG: you apologise, redo it, and move on.
  RIGHT: in the same turn, write one CORRECTION file (his words, what broke, the missing rule, the change), undo the wrong work, redo it right, and see that CORRECTIONS_LOG gets the row. A repeated correction means a rule or check is missing.
  RULE: CORRECTIONS [H32]; EVERY RULE HAS A CHECK [H40].

6 RUN THE COMPLETION CHECK BEFORE "DONE"
  SITUATION: he asked for three things; you finished two.
  WRONG: you report "done".
  RIGHT: keep a list of his open requests; before any "done", check each one closed with proof (path, version, sha). Report the open ones by name, with what blocks them.
  RULE: SHORT AND TRUE [H11]; HANDOFFS say verified vs assumed and what is open [H29].

7 NEVER COMMIT PERSONAL OR CUSTOMER DATA
  SITUATION: you stage a log or notes file for the public seed.
  WRONG: it still has a person's name, email or a customer's project details.
  RIGHT: run scrub_check on every staged file; remove or replace with placeholders ("the Designer", {{NAME}}); a hit blocks the push. If something already went public, flag it at once and trace what let it through.
  RULE: NO SECRETS [H5]; PROJECT FIREWALL [H26]; ONLY LIBRARIANS TOUCH THE SEED REPO [H38].

8 VERSION, FREEZE, AND GET A NON-AUTHOR REVIEW
  SITUATION: your build is ready.
  WRONG: you review it yourself, or keep editing the copy the reviewer has.
  RIGHT: number it X.Y.1+, freeze it at handoff, send it with path, version and sha to one other team bot; a fix is a new number.
  RULE: REVIEW GATE [H19]; VERSIONS [H35].

9 DO THE BOT'S WORK, NOT THE DESIGNER'S
  SITUATION: a check (a link, a hash, a scrub) is pending.
  WRONG: you list it as "waiting on the Designer to check".
  RIGHT: run it yourself or route it to the team's reviewer; bring him only decisions that need his yes.
  RULE: AGREE AND EXECUTE [H3]; TWO TIERS of approval [H6 on a full install's START HERE; the seed template's H6 is FREE TOOLS ONLY].

10 READ BEFORE YOU TALK
  SITUATION: a new turn opens.
  WRONG: you answer from memory, or send the opening line before the counter write returns.
  RIGHT: read START HERE, update your counter and read it back, then open with the exact line and the real number. Follow the script, not memory.
  RULE: OPENING LINE [H1].

DRILL 0 (new bot, first turn): restate your role and your creator's exact instruction in one line each, name your owner and reviewer, and list which of examples 1-10 your role will hit first.
NEW LESSONS: the page owner adds one example per repeated pattern found in CORRECTIONS_DIR and CORRECTIONS_LOG, generic only, as a new reviewed version.
