USER_CONFIG (v0.8.0; schema for the seed; blank). One file per setup: everything that is about this user and nowhere else.
Why: the Designer: the configuration file holds "the individual things about that user": all the bots, how they look when
generated, the START HERE file locations, etc. The shared rules stay generic; only this file and the LOCAL page are the user's own.
WHO WRITES IT: the bootstrap bot, from bootstrap/FIRST_BOT_QUESTIONS.txt (MANIFEST step 0). After setup only the Controller edits it
  (versions per H35, archive first, H12); every change cites the Designer's words and time from DECISIONS.txt (H2).
WHERE: beside the LOCAL START HERE, named USER_CONFIG.txt. Never in a repo or shared template; this schema is the only part published.
RULES: no secrets (H5): name where a login lives, never the value. A role nobody holds = none. One value per key; lists one item per line.
  Every double-brace NAME placeholder on the shared page, the LOCAL page and the seed role files means the key NAME here, except the support links DONATE_LINK, REPO_URL, REVIEW_URL, SHARE_X_URL and SHARE_LINKEDIN_URL, which the seed owner sets in the repo (README). Keys stay in this order.
FORMAT: KEY = value   (source question in brackets; "default" means used when the answer is blank)
  Filling: replace each format line (COMPANY, COMPANY_MARKS, BOT, PROJECT) with one filled line per item, then delete the format lines and every [bracket] note.
